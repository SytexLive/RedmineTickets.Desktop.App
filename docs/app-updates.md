# App Updates

This app uses the official Tauri v2 updater. Do not implement a custom
download-and-replace flow for updates.

## Runtime Flow

- `src/appUpdates.ts` wraps the JavaScript updater API.
- `App.tsx` calls `checkAndInstallUpdate()` once on startup in silent mode.
- The header action "Check for updates" calls the same function manually and
  shows a small status banner.
- On Windows, `downloadAndInstall()` launches the updater installer and Tauri
  exits the app as part of the install step.

## Tauri Configuration

- `src-tauri/src/lib.rs` registers `tauri-plugin-updater` and
  `tauri-plugin-process`.
- `src-tauri/tauri.conf.json` enables `bundle.createUpdaterArtifacts`.
- `src-tauri/capabilities/default.json` grants the frontend access to
  `updater:default` and `process:allow-restart`. Without these ACL permissions,
  the JavaScript updater fails with errors such as
  `Command plugin:updater|check not allowed by ACL`.
- The updater endpoint is GitHub Releases:
  `https://github.com/SytexLive/RedmineTickets.Desktop.App/releases/latest/download/latest.json`.
- `windows.installMode` is `passive` so users see installer progress without
  needing to step through the installer UI.

## Signing

Tauri updater artifacts must be signed. The public key is committed in
`src-tauri/tauri.conf.json`; the private key must never be committed.

Current local private key path:

```text
C:\Users\Dominik\.tauri\redmine-tickets.key
```

GitHub Actions must have these repository secrets:

```text
TAURI_SIGNING_PRIVATE_KEY
TAURI_SIGNING_PRIVATE_KEY_PASSWORD
```

For the current key, the password is empty. Store an empty secret value only if
GitHub allows it in the repository settings; otherwise set a real password and
regenerate/reconfigure the key pair.

## Release Flow

`.github/workflows/release.yml` performs two jobs:

1. `release` calculates the next semantic version, syncs version files, commits
   them, tags the release, and creates the GitHub Release.
2. `build-windows` checks out the release tag on `windows-latest`, builds the
   NSIS bundle with updater artifacts, uploads the installer/signature, and
   uploads `latest.json`.

`latest.json` is generated by `tauri-apps/tauri-action`. The app reads that file
on startup and from the manual header button.

Every push to `main` should create a new app version when there is at least one
commit since the previous release tag. `scripts/release-version.mjs` uses the
highest semantic level it finds:

- breaking change: major
- `feat:`: minor
- any other commit, including `fix:`, `docs:`, `chore:`, or non-conventional
  messages: patch

Keep this behavior unless the product decision changes. The updater only sees a
new version after the release workflow publishes a newer `latest.json`.

## Local Verification

Run these checks after touching update code:

```bash
npm test -- src/appUpdates.test.ts src/App.test.tsx
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

To produce signed update artifacts locally:

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY="C:\Users\Dominik\.tauri\redmine-tickets.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
npm run tauri build -- --bundles nsis
```
